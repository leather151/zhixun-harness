## 二、逐条对照

| # | 评测要求 | 我们的实现 | 结论 |
| --- | --- | --- | --- |
| 1 | 工业模型**从平台提供的检查点**开始 | 镜像 `ENV HARNESS_START_POLICY=previous`；`resolve_start_checkpoint()` 里 `--checkpoint → /previous → 镜像自带`。平台把上一轮选中的模型挂 `/previous`，我们从它续训 | ✅ |
| 2 | 每个数据集 **10 轮优化**，最终**隐藏测试**评测 | 轮次由平台驱动；容器每轮响应并产出 `/model/<TASK>/checkpoint.npz`。试运行实测 10/10 轮、A 隐藏 Macro-F1 0.8724、B 隐藏 RMSE 203.50 | ✅ |
| 3 | **Harness 调用 PyTRiO 大模型来读写代码、使用工具** | 原来只有"6 选 1 动作"。本轮新增 `harness/agent.py`：大模型**读实验台账摘要** → 输出**受白名单约束的实验规格**（recipe/epochs/lr/batch，等价于改训练配置/代码）→ 以 `python -m baselines.train` 为**工具**执行 → 候选仍交守门。开关 `--agent on`（默认 off） | ⚠️→✅ **代码已具备，但只在本机验证，未进任何已构建镜像** |
| 4 | 大模型 **≤27B**、可用微调 Sampler 或官方基础模型 | 默认 `Qwen/Qwen3.8-27B`（27B ✅），降级 `Qwen/Qwen3.5-4B`；自训 Sampler `trio://run_4e2okzovpr66/sampler_weights/zhixun-policy-v2`（LoRA on 4B），v14 起可用 SDK 的 `create_sampling_client(model_path=...)` 加载 | ✅（Sampler 加载链路未端到端验证） |
| 5 | **CPU 环境续训** | 工业模型是赛题方 `contest.cpu-mlp.v1` 单隐层 MLP（833–4,609 参数），纯 numpy 训练；无 GPU 依赖 | ✅ |
| 6 | **评分对象是续训后的工业模型** | 交付物 `/model/<TASK>/checkpoint.npz` 就是工业模型；大模型只做决策、不参与评测打分 | ✅ |

## 三、A/B/C 指标口径核对

| 数据集 | 官方口径 | 我们的记录字段 |
| --- | --- | --- |
| A 气体识别（6 类） | Macro-F1 越高越好，参考 Accuracy | `macro_f1`、`accuracy`（仅观测到的类别计入，与官方 `train.py::metrics` 一致） |
| B 轴承健康（分钟） | RMSE、MAE 越低越好 | `rmse`、`mae`、`bias`、`pearson` |
| C 发动机（循环） | RMSE 越低越好，参考 NASA 非对称评分 | `rmse`、`mae`、`nasa`（非对称：欠预测 exp(-d/13)-1，过预测 exp(d/10)-1） |

三项全部由官方 `train.py::metrics` 与 `harness/metrics.py` 两侧独立计算，口径一致。

## 四、必须让平台知道的两点（接口层面）

1. **模型访问的注入方式**：我们支持三种，任选其一
   - `HARNESS_LLM_CMD=<网关命令>`（**推荐**：请求 JSON 写 stdin，回复 JSON 读 stdout）
   - `HARNESS_LLM_CONFIG=<json>`（`endpoint|base_url|model_base_url`、`model`、`api_key`）
   - OpenAI 兼容 HTTP：`SAMPLER_ENDPOINT` + `SAMPLER_MODEL` + `SAMPLER_API_KEY`
   - 若要我们用自己的 Sampler 权重：设 `PYTRIO_BASE_URL` + `PYTRIO_API_KEY`，并让流程走 `/app/.trio-venv/bin/python /app/harness/trio_sampler.py`
2. **时间预算**：`HARNESS_MAX_SECONDS` / `HARNESS_MAX_WINDOWS` / `HARNESS_MAX_UPDATES` / `HARNESS_MAX_EPOCHS`
   可覆盖配置上限（取较小值）。即使被平台超时打断，产出已在盘上。

## 五、结论与建议

- **镜像 v12 满足 1/2/4/5/6 条**，且是**已被平台实证**的那一版（A 0.8724 / B 203.50）。
- **第 3 条（读写代码、使用工具）代码已补齐**，但只在仓库里、**不在 v12/v14 镜像内**，
  且默认关闭。要让平台侧真的看到"模型提出实验规格并被工具执行"，需要：
  1. 出一个 **v15**（= v12 + agent 层，`--agent on`），
  2. 用 **1 次试运行**确认：平台每轮记录里出现我们的 `agent_spec`（实验规格 + 工具执行），
     且 A/B 指标不退化。
- **风险提示**：agent 通道每轮多一次"大模型提议 + 一次真实训练"，会拉长单轮时间。
  若平台时间预算紧，用 `HARNESS_MAX_SECONDS` 收紧，或保持 `--agent off`（默认）。
