## 四、v6 相比 v5 改了什么（预检失败的根因）

一句话：**v5 的容器跑成功也会退出码 1**（`SystemExit(dict)` 的经典坑），平台只好判"运行失败"。

v6 同时修掉：

1. 退出码 → 成功必 0（真失败才非零，原因写 `/model/<TASK>/manifest.json` 的 `failure`）；
2. 补适配契约：`/app/CONTRACT.json`、`/app/ADAPTER.md`、`/app/models/<TASK>/meta.json`
   —— 预检不必再逐个翻源码（上一轮就是命令预算被翻代码耗尽的）；
3. 补 `/app/baselines/predict.py`（官方 `predict(model, inputs)` 同形桥，含 B 包必需的秩变换）；
4. 父检查点支持 `/previous`（8 种布局 + 兜底扫描 + 失败回落）；
5. 产物 **`/model/<TASK>/checkpoint.npz` 与 `/output/model/<TASK>/checkpoint.npz` 两处都写**；
6. **兜底交付**：入口先把内置检查点落盘再跑闭环，外部原因失败也不会让"不低于静态基线"变成 0 分。

容器内实测（构建脚本已自动验证）：三包 selftest 通过、默认 CMD 退出码 0、两处产物齐全。

## 五、Sampler 微调（上一版结论已订正）

**上一版清单写的是"PyTRiO 仅推理、拿不到 `trio://`"——这是错的，已实测推翻。**

- 推理用的 OpenAI 兼容接口只暴露 2 个 chat 模型，但**训练接口是可用的**：
  `create_lora_training_client` → `forward_backward` → `optim_step` → `save_weights_for_sampler`
  正常返回 `trio://run_.../sampler_weights/...`，控制台也能看到类型为 `sampler` 的权重。
- 我们用**自己 57 次真实闭环运行**里抽出的 87 条「窗口状态 → 动作+理由」轨迹，
  对 `Qwen/Qwen3.5-4B` 做了 LoRA rank 32 的行为克隆：44 步，loss 3.11 → 0.03，
  留出验证 4/5 命中，输出是严格可解析的决策 JSON。
- 完整记录（语料来源、损失曲线、验证明细、复现命令）：`提交材料\Sampler微调记录.md`。

策略层本身仍是「LLM 建议 + 规则兜底」：容器在封闭评测环境无外网，默认 `--policy rule`；
