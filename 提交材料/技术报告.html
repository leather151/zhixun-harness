2. 问题理解：为什么是“自进化系统”而不是“一个更准的模型”

赛题要求的是在漂移数据流上自动维持并提升模型性能的闭环：

漂移监测 → 诊断归因 → 实验优化 → 评估上线 → 回滚

三个公开数据集恰好各自提供一个真实的漂移剧本，我们据此设计并验证了闭环：

剧本训练分布上线分布漂移类型
Ab01 批次（445 条，全部类）b02 批次（1,244 条，类别比例不同）输入漂移 + 类条件漂移
B9 根轴承（其中 2 根占 71.6% 样本）另外 3 根（其中 1 根占 90.2%）整机尺度漂移 + 关系漂移
C496 台发动机（FD001–FD004）另外 106 台，工况与故障模式变化工况迁移 + 长尾

3. 系统架构

3.1 六个环节与实现位置

环节实现关键设计
漂移监测metrics.drift_report 每特征两样本 KS 统计量中位数、超 0.2 的特征数、均值漂移 |z|、预测分布偏移（均为无标签指标，可在线上直接计算）
诊断归因tasks.evaluate 按组误差分解：A 逐类召回、B 逐轴承 RMSE、C 逐子集 RMSE；同时输出漂移最大的 3 个特征名
实验优化tasks.fine_tune 调用官方 train_run 续训（低学习率、1 或 3 epoch），保留父检查点 sha256 与步数，可审计
评估上线runner 守门 冠军/挑战者：候选与现役在下一窗的已标注切片上对比，胜者才上线
回滚检查点栈 弹栈回到上一个被验证更好的模型，不需要重训
成本核算summary.json 训练秒数、epoch、更新次数、以及“每单位增益耗时”

3.2 策略层：LLM 决策 + 规则兜底（双保险）

策略器按固定接口 decide(state) → action 输出六种动作之一（hold / finetune_1ep / finetune_3ep / rollback / swap_candidate / recompute_stats）。默认自动探测平台注入的大模型接入信息 （SAMPLER_*、PYTRIO_*、OPENAI_* 等 5 组环境变量）， 找到就用 LLM 决策，找不到或调用失败就在同一处回落规则版。

为什么必须有兜底：门槛之一是“封闭评测中无人工干预跑完全部阶段”。若决策依赖一个评测环境里 不可用的外部模型，系统会直接挂。实测（把 SAMPLER_ENDPOINT 指向不存在的端口）： action=finetune_1ep / source=rule(fallback) / fallback=true / reason=URLError——容器照常跑完。 这条设计把“接 LLM”从风险变成了纯增益。

3.3 部署形态：一个镜像、三种入口

HARNESS_MODE行为用途
loop（默认）跑完自进化闭环，产物写 /output批量评测
servestdin JSONL 请求 → stdout JSONL 预测，自动识别 A/B/C若平台以管道喂样本
selftest秒级自检 + 三包各 1 条真实样本推理健康检查 / 上线前验证

镜像纯 CPU、无网络、只依赖 numpy==1.26.4；SwanLab 在镜像内默认关闭（SWANLAB_MODE=disabled）， 避免日志组件成为“跑不完”的原因。受限机制：窗口数、更新次数、epoch、秒数四道硬上限， 触发即停并写入事件流水。

参照RMSE（分钟）说明

进一步定位到两个结构性原因：① 训练集被两根长寿命轴承垄断（Bearing3_1+3_2 占 71.6% 样本， 而验证集 90.2% 来自 Bearing3_4）；② 同一剩余寿命在不同轴承上对应完全不同的特征数值 （起点与失效阈值不同），即“绝对水平不可跨轴承比较”。

4.2 A 包：一个少数类整体塌陷，且是跨批概念漂移

验证集 1,244 条中 109 条「乙醛」全部判错（108 条判成「乙醇」），该类 F1 = 0。 Macro-F1 为六类等权平均，因此 (0.857×5 + 0)/6 = 0.714——单类归零直接砍掉 1/6 的分数。

为判定“能否救回”，我们在批内做了「乙醇 vs 乙醛」二分类交叉验证：

数据1-NN5-NNLDA两类质心距离
b01（训练批）1.0000.9830.9920.751
b02（验证批）1.0000.9820.9850.384

判别信息存在（b02 内部 LDA 0.985），失败原因是 b01 的乙醛特征中心漂移到 b02 的乙醇附近—— 典型跨批概念漂移。

5. 工业模型优化

5.1 B 包：三个手段缺一不可（RMSE 681.16 → 369.47）

手段 1 · 秩变换：把每个特征替换为“在训练集里的分位”（201 个分位点，仅用 train.jsonl 拟合， 分位表随检查点保存，推理用同一张表）。作用是把“绝对水平”抹掉、只留“相对位置”，对单调漂移天然鲁棒。
手段 2 · 按轴承等权：样本权重 1/该轴承样本数，让 9 根轴承贡献相同。 只用训练集元信息做数据平衡，不作为模型输入。
手段 3 · 强正则 + 随机初始化 + 早停：weight_decay=1e-2（L2 只作用于 w1/w2）， 权重随机初始化，轮次由 train 内部留出的两根轴承选出（2 轮）。

配置（同一个 MLP，只改数据侧）官方 validation RMSEBias秩相关
原始特征 · 不加权 · 热启动658.42−321.5−0.299
原始特征 · 等权 · 热启动670.48−351.9−0.309
秩特征 · 不加权 · 随机 · wd=1e-2391.85+250.7+0.777
秩特征 · 等权 · 随机 · wd=1e-2（定稿）369.47−110.3+0.655
秩特征 · 等权 · 热启动 · wd=1e-3511.75−253.3+0.302
读法：秩变换给“方向”（秩相关 −0.30 → +0.78），按轴承等权给“尺度” （Bias +251 → −110），两者缺一不可；“热启动”会把方向破坏（511.8 vs 369.5）， 因为秩特征改变了输入语义，必须随机初始化。

逐轴承（before → after）：Bearing2_4 390.8 → 60.3、Bearing3_4 710.8 → 383.0、 Bearing1_4 242.0 → 235.4。并且首次越过常数基线 470.9（+21.5%）——这一条比降 45.8% 更有意义。

5.3 C 包：早停拿下，集成按性价比放弃

早停：轮次由 train 内部留出的发动机（每 5 台留 1）选出 16 轮 → RMSE 51.56（−2.5%）、MAE 37.98、NASA 分 5.82e9 → 3.20e9（−45%）； 四个子集全部不退化（FD001 42.83→40.7、FD002 41.15→41.0、FD003 55.36→52.4、FD004 63.24→62.0）。

集成（同初值多 shuffle + 权重平均）：5 成员得 51.37，只比单模型好 0.19（0.4%）， 却要 5 倍训练量 → 按资源效率不采用。附带一个有价值的结论： 权重平均只在“共享同一初值”时有效——随机初始化时 5 个成员落在不同盆地， 权重平均得到 79.28，而它们的预测平均是 51.60。

7. 工程与合规

要求本方案的做法
验证集只用于衡量--stream official 强制禁用一切更新动作；验证集不进梯度、不进标准化/分位表拟合、不参与选型与选轮次
选型不碰验证集轮次/配置只在 train 内部留出（A 按类分层时间尾、B 按整根轴承、C 按发动机）上选

9. 局限与后续工作

  1. A 包的乙醛：需要域自适应（非线性）或双模型门控。线性 CORAL 已证否； 门控方案证据已具备（筛特征模型乙醛 recall 0.982），但交付形态要从“单模型”改为“双模型 + 规则”， 本轮时间不足未做，明确列为未完成。
  2. B 包的选型代理失效：内部留出轴承（中短寿命）代表不了验证集里 1515 快照的长寿命轴承， 导致“内部最优”与“验证最优”不一致。已在报告中如实记录，后续应改为按寿命分层的留出。
  3. B 包的线性参照仍有优势：秩特征上岭回归 294.9 < MLP 369.5，说明模型容量/结构还有优化空间 （hidden 下调、或引入线性集成成员）。
  4. C 包的 FD004：仍占 54% 误差，未做按工况分组标准化。
