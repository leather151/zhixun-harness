# 系统运行说明（官方提交资料第 3 项）

> 赛题原文要求提交：①模型配置与 Harness 的系统镜像 ②完整的云端实验记录链接或查询依据
> ③**系统运行说明文档**。本文就是第 ③ 项。
> 队伍：赵文博（组长）｜赛题：智训引擎 · 工业制造场景下的模型训练与超参数优化

## 1. 一句话说明

镜像自带一个**工业模型自进化闭环**：读到新批次数据后自动做「漂移监测 → 诊断归因 → 实验优化 →
评估上线 → 回滚」，并留下可审计的实验记录；工业模型是赛题方 CPU 基线的自迭代产物，
驱动 Harness 的大模型使用 **PyTRiO 的 Qwen3.8-27B**（或选手经 PyTRiO 后训练的模型）。

## 2. 运行环境

| 项 | 值 |
| --- | --- |
| 基础镜像 | `python:3.12-slim` |
| 运行时依赖 | `numpy==1.26.4`（主运行时，唯一硬依赖） |
| 可选组件 | `/app/.trio-venv`：离线安装的 `pytrio` + `transformers`（用于加载选手自训的 sampler 权重；不污染主运行时） |
| 运行用户 | `runner`（uid 10001，非 root） |
| 网络 | 评测环境**离线**；只使用平台注入的 PyTRiO 服务（`SAMPLER_*` / `PYTRIO_*` 或 `HARNESS_LLM_CMD`） |
| 硬件 | 纯 CPU（三套基线参数量 833–4,609，无 GPU 需求） |

## 3. 入口（只有一个）

```bash
python -u /app/harness/entry.py        # 行为由 HARNESS_MODE 决定
```

| `HARNESS_MODE` | 作用 | 退出码 |
| --- | --- | --- |
| `loop`（默认） | 跑完整闭环，产物写 `/model/<TASK>/` 与 `/output/model/<TASK>/` | 0 |
| `serve` | 官方 predict 协议：stdin 一行请求 → stdout 一行结果 | 0 |
| `selftest` | 秒级自检 + 三包各 1 条真实样本推理 | 0=通过 |

镜像默认 CMD（等价）：

```
--task all --stream train --windows 4 --policy auto --swan off --out /output
```

常用参数：`--task all|A|B|C`、`--stream train|official|auto`、`--windows N`、
`--policy auto|rule|llm`、`--previous DIR`、`--model-out DIR`。

## 4. 平台每轮怎么调我们

| 平台动作 | 我们对应的入口 | 产物 |
| --- | --- | --- |
| 训练/续训一轮 | `python -m baselines.train --profile <A\|B\|C> --train … --validation … --from-baseline 父检查点 --output 新目录 --stage-id …` | `checkpoint.npz` / `training.json` / `history.jsonl`（父摘要与累计步数由官方 `train_run` 写入） |
| 只做预测 | `HARNESS_MODE=serve python /app/harness/entry.py` | 逐行 `{"outputs": …}`，按输入 schema 自动选模型 |
| 跑完整闭环 | 默认 CMD（`HARNESS_MODE=loop`） | `/model/<TASK>/checkpoint.npz` + `manifest.json` + 四个记录文件 |

## 5. 产物与记录（可审计）

| 文件 | 内容 |
| --- | --- |
| `/model/<TASK>/checkpoint.npz` | 交付模型（平台取件路径） |
| `/model/<TASK>/manifest.json` | `origin`（bundled/evolved）、sha256、父检查点、逐窗指标、上线/回滚次数、训练耗时、失败原因 |
| `/output/<task>-<stream>-<ts>/windows.jsonl` | 每窗的指标、漂移、归因、决策、守门结果 |
| `/output/<task>-<stream>-<ts>/decisions.jsonl` | 每窗决策原文：动作、`source`（llm/rule/fallback）、`model_used`、token 用量 |
| `/output/<task>-<stream>-<ts>/experiments.jsonl` | **四段式实验台账**：读历史 / 提假设 / 做实验 / 做决策 |
| `/output/<task>-<stream>-<ts>/report.md` | 人读版运行报告 |

## 6. 复现步骤（从零到跑通）

```bash
# 1) 自检（不需要数据，验证代码/模型/数据可达）
docker run --rm -e HARNESS_MODE=selftest zhixun-harness:v12

# 2) 官方 predict 协议
echo '{"inputs": {...}}' | docker run --rm -i -e HARNESS_MODE=serve zhixun-harness:v12

# 3) 完整闭环（挂载数据与输出）
docker run --rm -v /path/to/data:/data:ro -v /tmp/out:/output \
  zhixun-harness:v12 --task all --stream train --windows 4 --policy auto --swan off --out /output

# 4) 官方训练契约（单任务、单轮）
docker run --rm -v /path/to/data:/data:ro -v /tmp/round1:/work \
  zhixun-harness:v12 \
  python -m baselines.train --profile B \
    --train /data/B/train.jsonl --validation /data/B/validation.jsonl \
    --from-baseline /app/models/B/checkpoint.npz --epochs 2 --output /work/round-1 --stage-id round-1
```

## 7. 关键约束与受控机制

| 约束 | 实现 |
| --- | --- |
| 防无限制迭代 | `config.json` 硬上限：`max_updates=4`、`max_epochs=8`、`max_seconds=600`、`max_windows=12`；也可由 `HARNESS_MAX_SECONDS/WINDOWS/UPDATES/EPOCHS` 进一步收紧 |
| 验证集只测不改 | `--stream official` 强制 `updates_allowed=false`；标准化/分位表只在 train 上拟合 |
| 参数量 | < 100,000（当前 833 / 4,326 / 4,609） |
| 续训兼容 | 父检查点的 `hidden` 宽度与 `seed` 不可变，官方 `train_run` 会拒绝不匹配 |
| 兜底交付 | 入口先落内置检查点；中途失败也保证 `/model/<TASK>/checkpoint.npz` 在盘上，原因写 `manifest.failure` |

## 8. 故障与降级

| 情况 | 行为 |
| --- | --- |
| 平台未注入 PyTRiO 服务 | 先探测配置默认端点，不通则回落**确定性规则版**，保证"无人干预跑完" |
| 27B 端点拥塞 | 启动探测自动降级到 `Qwen/Qwen3.5-4B`；全不可用则规则版（决策记录写 `rule(fallback)` 与原因） |
| `/data` 未挂载或为空 | 回落镜像内 `data/public`；仍不可用则只用内置模型交付，退出码 0 |
| 父检查点 schema 不符 | 自动回落镜像自带模型，不中断 |
| 预测时遇到未知 schema | 按 `metadata.paths` 在所有检查点里匹配；匹配不到则提示先训练一轮 |
