# 《实验记录规范》对齐清单

> **重要说明**：官方《实验记录规范》原文**我们没拿到**。赛题 PDF 里它是"组委会提供的资源项"
> （原文：「平台与规范：提供评测平台 SDK、《实验记录规范》及云端实验记录平台」）。
> 本文做两件事：
> 1. 把我们已经记录的字段逐项列出来（**超集覆盖**常见规范要素，拿到原文后按需裁剪/改名即可）；
> 2. 标出"拿到原文后需要核对/补齐"的项，避免踩基础门槛②。

## 一、一个实验的完整记录（表格版）

以 `baselines/train.py` 的一次训练为例，`<output>/training.json` 里包含：

| 规范要素 | 我们记录的字段 | 值从哪来 |
| --- | --- | --- |
| 实验标识 | `stage_id`、`profile`、`seed` | 命令行传入 |
| 时间 | `created_at`（UTC）、`training_seconds` | 运行时测量 |
| **数据版本** | `train_sha256`、`validation_sha256`、`train_rows`、`validation_rows` | 对数据文件做哈希 |
| **代码版本** | `source_sha256`（model.py / data.py / train.py / predict.py 各自哈希）、`profile_sha256`（配置哈希） | 逐文件哈希 |
| 环境 | `numpy_version`、`python_version`、`machine`、`cpu_threads_requested`、`device` | 运行时读取 |
| **父模型** | `parent_checkpoint_sha256`（真实起点）、`initial_steps`、`initial_epochs` | 官方 `train_run` 写入 |
| 模型结构 | `parameter_count`、`input_features`、`configuration.hidden/activation/optimizer/…` | 检查点 metadata |
| 超参 | `learning_rate`、`batch_size`、`requested_epochs` | 命令行 + 配置 |
| **训练量** | `final_steps`、`final_epochs`（与 initial 相比可见"确实训练了"） | 官方 `train_run` 写入 |
| **结果** | `validation_before`、`validation_after`（A: acc/macro_f1；B/C: mae/rmse） | 训练前后各测一次 |
| 标签来源 | `label_provenance`（含 `target_unit` / `target_origin` / `target_definition`） | 配置 |
| 逐 epoch 明细 | `history.jsonl`：`epoch` / `step` / `loss` / `validation` | 每 epoch 追加 |

## 二、闭环决策的记录（门槛③专用）

`<output>/experiments.jsonl`，**每窗一行、四段式**：

| 规范要素 | 字段 | 示例 |
| --- | --- | --- |
| **读历史** | `read_history.prev_metric` / `ref_metric` / `history_actions` / `updates_used` / `epochs_used` | `prev_metric: 204.557, history_actions: ["finetune_1ep","rollback"]` |
| **提假设** | `hypothesis` | "已出现漂移信号：轻量续训（1 epoch、低学习率）可在低成本下缓解" |
| **做实验** | `change` | `finetune_1ep（epochs=1, 2.1s, steps [825, 1155]）` |
| **结果** | `result.metric` / `delta_vs_ref` / `drift_ks_median` / `drift_abs_z_median` / `by_group` | `metric: 190.862, delta_vs_ref: -13.696` |
| **做决策** | `decision.action` / `source` / `gate.adopted` / `gate.candidate_metric` / `gate.incumbent_metric` / `reason` | `adopted: false, candidate 247.7 vs incumbent 190.9` |

同目录还有：

| 文件 | 内容 |
| --- | --- |
| `windows.jsonl` | 每窗完整快照：指标、漂移全量统计、逐组归因、守门、执行结果、累计成本 |
| `decisions.jsonl` | 决策原文：动作、`source`（llm/rule/fallback）、`model_used`、`votes`、token `usage` |
| `report.md` | 人读版：逐窗指标表 + 事件流水 JSON |
| `manifest.json` | 交付模型：`origin`、sha256、父检查点、指标序列、上线/回滚次数、训练耗时、`failure` |

## 四、覆盖率自评

| 门槛②要求 | 状态 |
| --- | --- |
| 全部训练实验有记录 | ✅ 每次 `train_run` 都写 `training.json` + `history.jsonl`；SwanLab 另有 34 个 run |
| 全部调整实验有记录 | ✅ 每个消融（A 的 5 种方法、B 的 4 组对照、C 的集成尝试）都在 `实验日志.md` + SwanLab |
| 全部评估实验有记录 | ✅ `validation_before/after` 成对记录；`eval_delivered.py` 输出 `runs/delivered_eval.json` |
| 可追溯（谁/何时/什么/多少成本） | ✅ 时间戳 + 数据/代码哈希 + 父模型哈希 + `training_seconds` + token 用量 |
| **至少 3 次"读历史→提假设→做实验→做决策"** | ✅ 平台侧 30 条（3 任务×10 轮）；本地 `experiments.jsonl` 17 条；`decisions.jsonl` 256 条 |

## 五、拿到《实验记录规范》原文后要核对的三件事

1. **字段命名**：官方可能要求固定字段名（如 `experiment_id`、`dataset_version`、`metric_after`）。
   我们用的是自描述命名，**改名只是映射层**，不改数据。
2. **记录粒度**：是否要求"每次梯度更新"级、还是"每次实验"级。我们目前是**每次实验 + 每 epoch**，
   若要求更细（每步），`history.jsonl` 可扩成每 step 一行。
3. **上传方式**：是否必须在 SwanLab 且用特定 project 命名/标签。若是，我们只需把现有 run
   重命名或打 tag，不必重跑实验。

---

> 结论：我们的记录是**超集**（自描述命名 + 数据/代码/父模型三方哈希 + 成本字段）。
> 真正的风险不是"记不够"，而是**字段名与官方模板不一致**——拿到原文后做一次映射即可。
